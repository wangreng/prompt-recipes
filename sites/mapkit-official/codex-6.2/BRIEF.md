# Brief: official website for handdrawn-map-kit

Build the official website (single landing page) for **handdrawn-map-kit**: an AI/agent-driven hand-drawn illustrated cultural map engine (Node.js). Read `kit/README.md`, `kit/SKILL.md`, `kit/docs/`, `kit/examples/` to understand it. The kit is installed in `./kit` (run `cd kit && npx handdrawn-map ...`). `./kit` is read-only reference: do NOT modify files inside it except writing renders to `./kit/out` if needed, and never git push/commit/branch anywhere.

## Core idea (the owner's intuition)
The page is built ON a map generated by the kit itself. The whole page is one large hand-drawn map rendered by handdrawn-map-kit, and the explanations sit on top of it: what the library is, key features, how an agent calls it (inspect → YAML/JSON spec → render → `--diagnostics` JSON → fix loop; CLI; SKILL.md), and a quick start. For example, sections can be regions / islands / callouts / cartouches on the map. You decide the concept details.

## Hard requirements
- Use the kit itself as much as possible: the map(s), illustrations, cartouches, compass, labels, hand-drawn typography etc. should be rendered by handdrawn-map-kit (author new YAML specs for the site and render them; you may use custom inline SVG elements through the kit, styles presets, `--hd`). Hand-written CSS decoration should be minimal: CSS mainly for positioning text over the map, readable text blocks, code blocks.
- Commit the YAML specs you wrote and the render commands (a `build.sh`) so the site can be regenerated.
- Content must be accurate to the kit (real commands, real flags, real counts). No invented features.
- Polished and restrained. Readable text (contrast over the map). No generic SaaS look.
- Must work on desktop (1440 wide) AND mobile (390 wide). On mobile the map may crop/pan or a second portrait map spec may be rendered; text must stay readable.
- Static site: `site/index.html` + css (+ js if needed) + rendered images. Opens as a local file, no build step for viewing. Keep total images reasonable (< ~8 MB, use webp/jpg where fine).

## Verify before you say done
Screenshot your page at 1440×900 (first screen + full page) and 390×844 (first screen + full page) with headless Chrome/playwright, look at the PNGs, fix what looks wrong. At least 2 self-check passes. Put final screenshots in `shots/`.

When finished, write `NOTES.md`: concept in 3-5 lines, which parts are kit-rendered vs hand-coded (rough % of visible page area that is kit-rendered), known issues.

## Hero demo (owner's addition)
The hero demo is ONE command that generates this very site. Provide a real script in this folder (e.g. `./build.sh`, or `npx handdrawn-map render site.yaml ...` plus a tiny build script that uses only the kit) that reproduces the whole page end to end from the specs: render all maps/images and write `site/`. Show that exact command on the page as the hero demo. Verify it: delete the generated renders in `site/`, run the command, confirm the page is rebuilt identically (screenshot again). Mention the result in NOTES.md.

## Additional requirements (owner, round 2)
- The ENTIRE page background must be ONE continuous kit-drawn map from top to bottom (no plain CSS background areas between sections). Each section carries its own small kit illustrations/objects scattered around it.
- Strong, uncluttered hero: big headline beside a real-geography map (Natural Earth) with kit illustrations, plus the one-command self-build demo.
- The one-command build must work on a clean machine with only Node.js and the kit installed (no ImageMagick or other tools).

- Mobile 390: the FIRST SCREEN must already read as a map: kit cartouche, compass and border visible, and the section content sitting on a kit-drawn parchment island with small kit objects around it. Not a plain text hero with the map pushed below the fold.
